# TaskMaster: полноценный диспетчер задач и управление ПК

## Цель и порядок работ

Единое нативное приложение для замены штатного Диспетчера задач Windows и
Microsoft PC Manager. Исходная реализация — MASM x64, Win32, без стороннего
runtime. Приоритет пользователя от 10 ноября 2026 года: **процессы и мониторинг
Диспетчера задач прежде функций PC Manager**. Общая цель не сокращается до
перехвата запуска taskmgr.exe, очистки памяти или текущих возможностей программы.

Этот документ фиксирует проверяемый объём и очередность. Будущие функции ниже
не считаются реализованными. Пользователь подтвердил окно запуска новой задачи
и поручил дальнейшую реализацию карты самостоятельно, без согласования каждого
сценария. Дизайн и проверки фиксируются в репозитории; исправления существующих
функций выполняются по мере обнаружения.

Последний проверенный этап — метаданные массовой таблицы от11 ноября2026:
16 настраиваемых полей, пользователь/путь/командная строка через три независимых
фоновых канала и ограниченный кеш, дескрипторы из текущего снимка, сохранение
старого макета V1 в V2. Все16 шагов `verify-development.ps1` прошли без пропусков

столбцов; по умолчанию остаются прежние семь. Следующий блок этапа1 — аппаратный
мониторинг и данные GPU по процессам с явной доступностью источников.

## Этап 1 — достоверные процессы и мониторинг (текущий приоритет)

1. Исправить ложноположительный результат нативных тестов в Windows PowerShell
   5.1. Ненулевой native exit, невозможность узнать exit, ошибка запуска и timeout
   должны завершать проверку ошибкой. Таймаут останавливает только свой процесс.
2. Исправить независимость UI-тестов от DPI и ширины тестового окна, сохранив
   проверки реальной отрисовки и проверки отзывчивости на 5000 строках.
3. Восстановить действительные CPU affinity actions и проверить чтением обратно
   на отдельном дочернем процессе, включая отказ для устаревшей идентичности.
4. Реализовать CPU потоков между наблюдениями. Проверять TID+время создания и
   владельца, числовую сортировку, первый/невалидный интервал и RU/EN формат.
5. Устранить потерю порций служб при `ERROR_MORE_DATA`, проверить ограниченный
   буфер, отмену и граничное число строк.
6. Добавить запуск новой задачи и полноценную таблицу подробностей процесса:
   пользователь, путь, командная строка при доступности, время запуска,
   дескрипторы, private commit, working set, I/O и настраиваемые колонки.
7. Расширить аппаратный мониторинг: отдельные ядра CPU, диски, сетевые адаптеры,
   GPU, доступные engine counters и данные по процессам. Отсутствие прав/счётчика
   отображать явно. I/O процесса не называть физическим диском, а суммарную сеть
   интерфейсов не выдавать за атрибуцию конкретному процессу.

Приёмка этапа: сборки standard/admin, native/model/UI/integration проверки,
сверка новых показателей с независимым Win32/API наблюдением на контролируемой
нагрузке; проверка стабильного выбора и числовой сортировки; отсутствие блокировки
UI при переключении и недоступности источников. Существующий `verify-build.ps1`
проверяет только свойства PE и размер, а не этот функциональный объём.

## Этап 2 — завершение рабочих сценариев Диспетчера задач

Настраиваемые подробности, процессы по пользователям/сеансам, подтверждённые
действия выхода и отключения, управление службами и автозагрузкой с диагностикой
прав. Для изменения состояния сохраняются проверка идентичности, отдельный
результат каждой операции и отказ при устаревшем объекте. Операции над потоками
покрываются проверкой владельца и независимых suspend counts. Поддержка нескольких
processor groups не заменяется одной 64-битной маской без объяснения ограничений.

Приёмка: сценарии standard/elevated, исчезновение объекта во время действия,
смена PID/TID, отказ доступа, системные/защищённые процессы, несколько сеансов,
перезапуск и восстановление настроек. Тесты действий используют собственные
фикстуры, а не рабочие процессы, службы и автозагрузку пользователя.

## Этап 3 — функциональность PC Manager

1. Фоновый анализ хранилища с выбранными корнями, прогрессом, отменой, сведениями
   о пропущенных/недоступных данных. Не следовать reparse points молча.
2. Крупные файлы, загрузки и дубликаты: реальные размеры и пути, фильтры, открытие
   расположения. Для дубликатов совпадения имени/размера недостаточно.
3. Очистка: отдельное сканирование, просматриваемый список, явный выбор,
   повторная проверка идентичности перед изменением, корректная обработка занятых
   файлов, действительный итог. Личные документы и загрузки не удаляются по
   умолчанию. Пакетный результат содержит успехи, пропуски и ошибки.
4. Инвентаризация и удаление приложений через поддерживаемые системные механизмы.
5. Диагностика Windows Security/Update, автозагрузки, занятого места и ресурсов
   с объяснимыми результатами, без универсальной выдуманной оценки «здоровья».
6. Системные инструменты, браузер по умолчанию и управление мешающими окнами
   через поддерживаемые возможности Windows и явные пользовательские настройки.

Каждая новая подсистема проходит отдельный дизайн, native/fixture тесты и
проверку интерфейса. Доступ к настройкам Windows допустим как системное действие,
но простая ссылка на настройки не заменяет требуемые анализ/инвентаризацию/отчёт.

## Этап 4 — выпуск и общие критерии готовности

- Windows 10 x64 и Windows 11 x64 проверены отдельно; точные минимальные сборки
  Windows и доступность каждого API записаны до выпуска.
- RU/EN, светлая/тёмная тема, DPI 100/150/200%, клавиатура, screen-reader сценарии,
  минимальный размер окна, большое число записей и длительная работа проверены.
- Числа, нулевые значения, недоступные данные, неполные суммы и интервалы
  наблюдений различимы. Выбор строки следует идентичности, а не индексу.
- Работа с обычными правами полезна; повышение прав имеет понятную причину.
  Отказ UAC, выключенный источник данных и ошибки API не приводят к падению.
- Измерены CPU/RAM самого приложения, задержки UI, отмена фоновых операций,
  завершение потоков и отсутствие утечек ресурсов при длительной работе.
- Установка/обновление/удаление, восстановление IFEO и пользовательских настроек,
  подписание доступным сертификатом, контрольные суммы и релизная документация.
- Перед завершением общей цели каждый пункт этой карты получает актуальное
  доказательство; зелёный набор узких тестов не доказывает весь продуктовый паритет.

Общая цель остаётся активной, пока есть отсутствующие или непроверенные требования.
