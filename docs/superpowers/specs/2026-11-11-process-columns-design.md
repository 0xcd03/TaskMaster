# Настраиваемые столбцы процессов

Этап продолжает пункт6 ROADMAP и уже проверенное окно сведений. Пользователь
поручил самостоятельно выполнять карту без согласования отдельных сценариев.
Это изменение архитектуры таблицы: её постоянные идентификаторы полей должны
перестать зависеть от номера видимого subitem. Сохраняется MASM x64/Win32.

## Результат и границы

Команда «Выбрать столбцы…» в меню представления и меню заголовка открывает
нативный EN/RU диалог. Флажки определяют видимость; кнопки вверх/вниз и
перетаскивание заголовков — порядок; обычное изменение ширины — размер.
Имя обязательно и закреплено первым для дерева/иконок. PID обязателен, но
перемещается. OK применяет полный валидный макет; Cancel не меняет таблицу и
файл. Defaults меняет только черновик до OK. Доступно во время actionBusy;
изменений процессов не выполняет. Ошибка записи оставляет рабочий макет в памяти
и показывается в диалоге/его результате, без ложного сообщения об успешном сохранении.

Начальные семь столбцов и их смысл сохраняются. Дополнительные пять используют
уже имеющийся снимок, без новых фоновых чтений:

| ID | Поле | Источник |
| --- | --- | --- |
| 0 | Имя | row+0 / tree name+3744 |
| 1 | Статус | DWORD+3884 |
| 2 | CPU | DWORD+3900, valid+3672; дерево+4040/4056 |
| 3 | Working set | QWORD+3632, valid+3656; дерево+3728, известно если unavailable+3712 < total+3736 |
| 4 | I/O read+write KiB/s | QWORD+3888, valid+3896; дерево+4048/4060 |
| 5 | Потоки | текст+1536, число Toolhelp |
| 6 | PID | DWORD+3584 |
| 7 | Родительский PID | DWORD+3588, текст+1024; относится к самому процессу |
| 8 | Private commit MiB | QWORD+3624, valid+3656; дерево+3720, известно если unavailable+3712 < total+3736, текст+3752 |
| 9 | Запуск UTC | FILETIME+3600, ноль недоступен; относится к самому процессу |
| 10 | Прочитано байт процессом | QWORD+3640, valid+3660; без агрегации потомков |
| 11 | Записано байт процессом | QWORD+3648, valid+3660; без агрегации потомков |

Private commit не называется private working set. I/O включает недисковые
источники. Невалидное поле не выдаётся за ноль. Время UTC форматируется явно.
Существующие сведения пользователя/пути/command line/handles пока доступны
в закреплённом окне; массовые столбцы этих полей потребуют отдельного ограниченного
кеша PID+birth. Этот этап не завершает весь пункт6 или полную замену приложений.

## Модель и хранение

Один макет представления Processes для пользователя, а не на каждый PID.
Постоянный ID поля совпадает с таблицей выше; добавления имеют новые ID.
Видимые физические subitems получают `pcVisibleIds[]`; визуальная перестановка
заголовка не меняет это соответствие до следующего пересоздания столбцов.
Макет хранит видимые ID в визуальном порядке и ширины всех12полей в единицах96DPI.
При скрытии текущего sortID сортировка явно возвращается к имени по возрастанию.
Числовые значения сортируются численно, недоступные в конце в обоих направлениях,
равенства разрушаются PID+birth. Сортировка других панелей сохраняет их прежний смысл.

`process_columns_contract.inc` задаёт record128bytes/version1:
DWORD size0,version4,count8,sortID12,descending16,reserved20;
DWORD visibleIDs[12]24..71; DWORD widths96[12]72..119; QWORD reserved120.
Count2..12, ID0первый, ID6есть, все видимые ID уникальны0..11,
неиспользованные ID=FFFFFFFFh, widths32..4096, sortID видимый, descending0/1,
reserved0. Валидируется весь record до применения; ошибки не частично исправляются.
Defaults: count7, IDs0..6, sort0/ascending; widths
240,130,76,120,125,90,68,90,150,190,140,140.

Отдельный `%LOCALAPPDATA%\TaskManagerX64\process-columns-v1.bin` не затрагивает
существующий settings.ini. Загрузка принимает ровно128байт и валидную версию;
отсутствующий/повреждённый файл даёт defaults с диагностическим кодом загрузки.
Сохранение: проверка record, уникальный принадлежащий нам временный файл рядом,
полная запись/FlushFileBuffers/закрытие и атомарная замена. Ошибка сохраняет старый
файл; временный файл удаляется только если создан этой операцией. PathAPI явный,
длина не более1023WCHAR+NUL; тесты используют только собственные временные пути.
Файл содержит только макет, ни одного значения процесса.

## Нативная таблица

`SetModeColumns` захватывает старый макет до удаления по собственному
`pcAppliedMode/pcAppliedDpi`, а не по уже изменённым frontMode/uiDpi. Удаляется
фактическое количество столбцов. Процессный макет восстанавливается при смене панели,
темы/дерева/DPI; сортировка процессов хранится отдельно от других панелей.
Ширины захватываются с DPI старой таблицы, а применяются с новым DPI.

Вся диспетчеризация текста, column-click, heatmap и заголовка переводит physical
subitem в stableID. Дерево сохраняет Name как physical/visual0. Фон справа от
заголовков вычисляется по правой границе всех прямоугольников, не последнему
логическому индексу. Native header drag разрешён только для Processes; перемещение
имени и вставка другого поля перед именем отклоняются. Endtrack/itemchange/enddrag
планируют одно coalesced сообщение8063h; снимок геометрии снимается после применения
операции Windows, а не внутри ещё не завершённого enddrag. При программном
пересоздании notifications игнорируются. Сохранение последнего макета происходит
также перед сменой режима и завершением главного окна.

## Проверки

Pure/store tests: defaults, все128байт roundtrip, canaries/no mutation on errors,
count/ID/duplicate/mandatory/sort/reserved/version/width границы, truncation/trailing
bytes, неизвестная версия, недоступный путь, отказ записи с сохранением прежних
байт, owned-temp cleanup. Перезапуск отдельного fixture подтверждает загрузку.

Реальный hidden ListView: убрать CPU, показать пять новых полей, переместить PID,
изменить ширину, прочитать соответствие/порядок/ширины. Реальный notification click
после перестановки сортирует2/10/100 и QWORD>32bit, unknown и равенства; выбор
PID+birth сохраняется после snapshot/сортировки. Проверяются текст/heatmap/header,
дерево и name/icon0, другие панели, DPI96/144/192, обе темы и EN/RU.
Диалог: реальные флажки/порядок/обязательные поля/Defaults/Cancel/OK и отказsave.
Тесты не вызывают production LoadSettings и не меняют пользовательский файл.
RED до реализации, GREEN и значимая mutation; полный aggregate после интеграции.
