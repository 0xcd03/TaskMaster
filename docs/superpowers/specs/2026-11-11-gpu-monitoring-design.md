# GPU monitoring design

Authorized product direction: retain native MASM x64; expand Processes and monitoring autonomously. This block implements per-process GPU and adapter measurements. CPU topology, physical disks and network interface monitoring remain subsequent blocks in the full Windows Task Manager / PC Manager replacement roadmap.

## User behavior

Processes gains four optional stable columns: GPU utilization, GPU engine, dedicated GPU memory, shared GPU memory. Values belong to the process itself, including in tree view. Numeric sorting uses numeric values, unknown values last in either direction, then stable PID and full creation time. GPU engine sorting uses adapter LUID / physical index / engine index. Existing selections, layout and actions survive refreshes. Status displays distinguish warm-up, measured zero, missing, unavailable, partial and stale values; never format invalid data as zero. Memory is bytes rendered with the existing formatter.

Performance displays adapter identity (DXGI name when mapped, otherwise LUID), software flag, physical index, current utilization, dedicated/shared usage and respective capacities. Capacity and usage are distinct. Global GPU load is the busiest physical engine. Process GPU load is its busiest engine across adapters. Adapter engine load sums process contributions on that physical engine before choosing the busiest engine. Process memory is aggregated across distinct adapter/physical pairs; it is never summed to obtain adapter memory. Known Windows 10 GPU Process Memory counter limitations must be explained in documentation and exposed in a relevant UI source/detail caption. DXGI enumeration order is not claimed to equal Windows Task Manager GPU numbering.

## Ownership and lifecycle

The ABI and exact offsets are authoritative in `src/gpu_contract.inc`. Preserve existing 4096-byte process row and historical snapshot ABI. GPU frames are independent, immutable after publication. One fixed sampler thread owns PDH, scratch buffers, DXGI objects and prior PID/birth baselines. One latest-frame mailbox replaces unread results. UI takes ownership of its front frame; render and comparison perform bounded in-memory lookups only. Main collector copies only the small summary. No provider/heap calls under worker lock. Stop is asynchronous; no replacement threads when a provider blocks. At most one working, ready and UI-owned frame; 2,982,144 bytes each.

Demand is global for Processes/Performance; request process counters only for visible GPU columns (engine counters are also global). Every mask/window change advances epoch and invalidates summary, ready frame and failure. Old completions cannot publish. A fixed allocation-failure mailbox still clears old UI data. One-second sampling, three-second freshness, five-second maximum utilization interval. Query failures, epoch changes and gaps reset utilization baseline; memory gauges may succeed immediately. Publish sequence and observation interval; chart updates only for new valid observations and uses gaps rather than repeating old data.

## Data correctness

Strict bounded parsers accept complete English PDH instance grammar; decimal DWORDs and exact 8-digit hex halves. Engine suffix may contain spaces; full string is validated even when display is truncated. Typed keys are LUID / physical index / engine, never truncated names. Validate array count, 24-byte stride, all name pointers/alignment/NULs within returned buffer, item CStatus 0/1, finite nonnegative utilization and nonnegative signed LARGE memory. Empty arrays are unavailable. Duplicate exact measurement keys, malformed items, arithmetic overflow or capacity overflow mark the entire source partial; they cannot publish a misleading valid zero. Convert grouped double utilization to rounded basis points and clamp to 10000. Equal load ties use ascending unsigned LUID, physical index and engine ID, independent of enumeration order.

Bounds: 8192 processes, 16384 process hash slots, 64 adapters, 4096 physical engines, 8 MiB provider array scratch, three bounded sizing attempts. A nonzero-buffer PDH_MORE_DATA triggers a new zero-size probe. Per-counter addition, collection, formatting and metadata errors remain distinct. Retry missing counters / refresh DXGI at most every 30 seconds. PDH query and COM resources close on provider shutdown.

PDH names carry only PID. After reading, resolve each nonzero PID using a held limited-query handle, GetProcessId and GetProcessTimes. Process memory requires creation time no later than sample begin. Utilization additionally requires the same PID + creation time in the preceding successful raw sample, with creation no later than baseline. Unknown/reused identity invalidates process fields; it does not erase separately measured adapter/global totals. Provider retains only a compact previous identity map and no published frame pointer. UI requires exact row PID + creation match. This mitigates PID reuse without claiming birth identity is supplied by PDH.

## Layout compatibility

Stable IDs 0..15 retain meaning; new IDs 16..19. V3 record stores 64 ID/width slots (544 bytes): header 24, IDs at24, widths at280, reserved tail at536. Actual current count20. This reserves schema space for the broader roadmap without immediately requiring another storage version. Strict legacy V1 128-byte and V2 160-byte readers migrate order, widths and sort. V3 filename `process-columns-v3.bin`. Fall back V3 -> V2 -> V1 only for ERROR_FILE_NOT_FOUND; corruption/access errors stop fallback, report diagnostic and use defaults. Legacy files remain untouched. Unused ID slots are -1 and width slots valid defaults. Whole-record validation and transactional replacement remain mandatory.

## Validation

Meaningful behavioral RED/GREEN parser, aggregation, invalid status/zero, duplicate, bounds, overflow and PID reuse tests; provider seams test independent errors, array growth and query lifecycle; worker tests cover bounded threads/mailbox, epochs, failure, staleness and shutdown. Native UI fixtures cover four columns, sorting, selection, freshness, demand and persistence migrations. Current machine supports English PDH counters and AMD GPU plus software renderer. Run a bounded owned GPU workload where feasible and compare observed identity/utilization/memory; do not claim Task Manager parity solely from synthetic fixtures. Retain all existing gates, production PE security and 256 KiB size gate. Missing hardware is an explicit limitation, not an unreported skipped gate.
