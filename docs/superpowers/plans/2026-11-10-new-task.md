# Native Run new task implementation plan

> **For agentic workers:** use superpowers:subagent-driven-development for the independent engine and dialog tasks; parent integrates and verifies the combined tree.

**Goal:** launch an explicitly chosen executable from TaskMaster with literal arguments, working directory, current rights or explicit UAC elevation.

**Architecture:** a native launch engine owns process creation and error results. A separate native dialog owns its input buffers and presentation; command 2500 routes directly from the existing main menu handler. Existing process actions and collector remain independent.

**Tech stack:** MASM x64, Win32, Windows SDK, native resources, PowerShell 5.1 test runner.

**Spec:** `docs/superpowers/specs/2026-11-10-new-task-design.md`.

## Global constraints

- Preserve existing uncommitted monitoring repairs and downloaded `outputs/` releases.
- EN/RU, standard/admin configurations, no new third-party runtime.
- Shared request offsets are 0/8/16/24; LaunchNewTask returns a Win32 error.
- No real UAC prompt, user-app termination, system settings changes or publishing in tests.
- Only fixture programs execute during automated launch verification.

## Ownership and execution record

Engine and dialog implementers own disjoint modules. Parent alone changes menus,
resource generator, main include/routing, verification coordinator and docs. Shared
working tree is retained to preserve prior uncommitted improvements, on the task's
`codex/task-manager-new-task` branch; no second checkout can silently omit them.
This is deliberate local branch isolation, with no remote push or merge.
